# Power BI Dashboard 设计方案（面试展示版）

> **设计原则：从业务问题出发，不堆砌图表。每个页面回答一个核心业务问题。**
>
> 面向面试官展示：SQL 分析能力 · 用户增长分析 · 用户分层 · 可视化 · 业务洞察

---

## 全局设计规范

### 设计理念

```
业务问题 → 分析框架 → KPI 指标体系 → 图表设计 → 交互路径 → 业务结论
```

每页遵循"看板思维"：
- **顶部**：核心 KPI 卡片（3-5 个）—— 3 秒获取页面结论
- **中部**：诊断图表（3-4 个）—— 回答"为什么"
- **底部/右侧**：明细与行动清单 —— 回答"怎么办"

### 配色与视觉

| 用途 | 颜色 | Hex | 语义 |
|------|------|-----|------|
| 购买/正向 | 品牌绿 | `#27AE60` | 转化、增长、达成 |
| 收藏 | 暖橙 | `#F39C12` | 兴趣、中间环节 |
| 加购 | 品牌蓝 | `#2980B9` | 意向、行动 |
| 浏览 | 中性灰 | `#95A5A6` | 曝光、流量 |
| 警告/流失 | 警示红 | `#E74C3C` | 流失、风险、需关注 |
| 高价值 | 深蓝 | `#1B3A5C` | 核心用户、品牌 |
| 背景 | 浅灰 | `#F8F9FA` | 页面底色 |

### 全局筛选器（所有页面共享）

| 筛选器 | 类型 | 数据源 | 默认值 |
|--------|------|--------|--------|
| 日期范围 | 日期切片器 | `dim_date.dt` | 全部 |
| **工作日/周末** | **切换按钮** ⭐ | `dim_date.is_weekend` | 全部 |
| 行为类型 | 多选复选框 | 固定值：PV / FAV / CART / BUY | 全选 |

> **周末切换很重要**：周末 DAU+16% 但购买率-10%。切换此按钮可对比两种模式下的全页指标——这是最有运营价值的全局交互。

### 全局交互规则

- **跨页联动**：点击漏斗某阶段 → 下钻到留存页对应群体
- **钻取路径**：总览 → 诊断 → 明细 → 行动清单
- **悬停提示**：所有图表悬停显示具体数值和同环比
- **书签导航**：页面左侧固定导航栏，支持一键跳转

## Page 1 — Executive Overview（高管概览）

### 回答的核心业务问题

> **"平台整体健康状况如何？钱花在哪、人从哪来、增长卡在哪？"**

### 页面目标

让面试官在 **10 秒内**理解项目全貌：数据规模 → 核心指标 → 最大问题 → 增长杠杆。这是"电梯演讲"的可视化版本。

### KPI 卡片（页面顶部，5 张）

| # | KPI | 数值 | 数据表 | 字段 | 业务含义 |
|---|-----|------|--------|------|----------|
| 1 | **总用户数** | 28.7 万 | `profiling_summary` | WHERE metric='total_users' | 分析覆盖的活跃用户规模 |
| 2 | **整体购买率（用户维度）** | 67.97% | `user_conversion_summary` | `buy_rate_pct` | 至少购买过1次的用户占比 |
| 3 | **行为→购买转化率** | 2.01% | `profiling_summary` | WHERE metric='buy_pct' | 每次行为的购买概率 |
| 4 | **日均 DAU** | ~2.5 万 | `daily_behavior_summary` | AVG(dau) | 日活规模 |
| 5 | **高浏览低转化用户占比** | 29.3% | `user_cluster_summary` | WHERE cluster=3, `user_pct` | 最大增长机会群体规模 |

> **设计要点**：数字要大（24-28pt），KPI 下方用小字标注同比/环比（可用 Day1 vs Day7 趋势替代）。红色标注"2.01%"和"29.3%"——这是两个需要面试官关注的关键数字。

### 图表区（4 个核心图表）

#### 图表 1：用户行为转化漏斗（Funnel）

#### 图表 2：DAU 与购买率双轴趋势（Dual Axis Line）

| **业务解读** | "周末 DAU 显著高于工作日（+122%），但购买率是否同步提升？" |

| 属性 | 内容 |
|------|------|
| **图表类型** | 水平柱状图 + 颜色编码 |

| **Y 轴** | 分群名称 (persona_name) |

| **业务解读** | "29.3% 的用户（红色区域）购买率仅 0.8%——这是最大的 GMV 增长杠杆。" |

### 交互设计

| 交互 | 触发 | 行为 |
|------|------|------|
| 漏斗图点击 | 点击漏斗某个阶段 | 跳转到 Page 2，并高亮该阶段 |
| DAU 趋势日期选择 | 框选日期区间 | 更新全页 KPI 为该区间汇总 |
| 分群柱状图点击 | 点击某个 Cluster | 跳转到 Page 5 该分群详情 |
| 留存曲线悬停 | 悬停 D1/D7 点 | 弹出 Tooltip："D1 留存 = 78.8%（11/25 Cohort），D7=98.5% 为周末回峰" |

### Drill-Down 设计

```
Page 1 总览
  ├─ 点击漏斗 → Page 2 漏斗与留存（诊断断裂原因）
  ├─ 点击 DAU 趋势 → Page 3 用户行为（分析活跃规律）
  ├─ 点击分群柱状图 → Page 5 用户分群（查看策略）
  └─ 点击留存曲线 → Page 2 留存热力图（Cohort 维度分析）
```

### 页面结论

> **"平台拥有 28.7 万活跃用户，行为→购买转化率 2%。关键发现：周末 DAU+16% 但购买率-10%（流量质量错位），用户跳过收藏直接加购（收藏非必要环节），C1+C0 占 49.4% 用户但购买率 <2%（最大增长杠杆）。51.3 万件问题商品消耗推荐资源。"**

### 页面业务价值

- **面试展示**：1 页讲完项目全貌，展示"宏观视角 + 反直觉发现"的能力
- **业务决策**：管理层一眼看到"该把资源投在哪里"——提升转化而非拉新
- **叙事逻辑**：规模 → 问题 → 反直觉发现 → 机会 → 行动入口
- ⭐ **反直觉发现卡**：页面右下角放置"你知道吗？"卡片——"周末流量↑16%，购买率↓10%——'逛'与'买'的时间错位"

## Page 2 — Funnel & Retention（漏斗与留存）

### 回答的核心业务问题

> **"用户在哪里流失？为什么流失？如何降低流失？"**

### 页面目标

深度诊断转化链的断裂点和用户流失的时间规律，定位可优化的**具体环节**和**时间窗口**，为产品/运营提供明确的优化方向。

### KPI 卡片（页面顶部，5 张）

| # | KPI | 数值 | 数据表 | 字段 | 业务含义 |
|---|-----|------|--------|------|----------|
| 1 | **PV → FAV 转化率** | 39.8% | `funnel_summary` | WHERE stage='fav', `conversion_rate_pct` | 浏览用户中有多少产生收藏兴趣 |
| 2 | **FAV → CART 渗透率** | 75.3% | `funnel_summary` | WHERE stage='cart', `conversion_rate_pct` | 收藏后加购的比例 |
| 3 | **CART → BUY 转化率** | 68.3% | `funnel_summary` | WHERE stage='buy', `conversion_rate_pct` | 加购后完成购买的比例 |
| 4 | **Day 1 留存率** | 78.8% | `cohort_retention_detail` WHERE cohort='11/25' AND day=1 | 次日回访率（11/25 Cohort） |
| 5 | **加购未购用户数** | 20,089 | 计算：has_cart=1 AND is_buyer=0 | 最高意向的未转化群体 |

> **设计要点**：KPI 1（PV→FAV 39.8%）用红色背景高亮——这是核心问题指标。其他用绿色（健康）到黄色渐变。KPI 下方用小字标注"阶段流失率"：KPI1 = 60.2% 流失，KPI5 = 92.4% 累积流失。

### 图表区（5 个核心图表）

#### 图表 1：转化漏斗 — 多路径 Sankey 图 ⭐（替换原单路径漏斗）

| 属性 | 内容 |
|------|------|
| **图表类型** | **Sankey 图**（多路径流向图）→ 替换原单路径漏斗图 |
| **数据源** | `funnel_summary` + 交叉计算 |
| **流向** | PV → FAV（113,717）、PV → CART（跳过收藏，~101,450）、PV → BUY（直接购买）、FAV → CART、FAV → BUY、CART → BUY |
| **颜色标注** | 跳过收藏的流向用蓝色高亮（反直觉发现的视觉锚点），PV→FAV 用橙色（标准路径） |
| **业务解读** | "加购用户远多于收藏用户——用户行为是'浏览→加购→购买'，不是'浏览→收藏→加购→购买'。收藏不是必要环节。" |

#### 图表 1b：FAV vs CART 渗透率对比 ⭐（新增）

| 属性 | 内容 |
|------|------|
| **图表类型** | 并列柱状图（2 组 × 2 柱） |
| **数据源** | `user_conversion_summary` |
| **展示** | 全体用户 FAV 渗透率(39.6%) vs CART 渗透率(75.0%)，购买用户 FAV 渗透率(41.4%) vs CART 渗透率(79.1%) |
| **业务解读** | "购买用户的收藏率与全体用户几乎持平（41% vs 40%），说明收藏不是购买的必要前置——加购才是。" |

#### 图表 2：FAV 收藏渗透率 vs CART 加购渗透率对比

| 属性 | 内容 |
|------|------|
| **图表类型** | 并列柱状图 |
| **数据源** | `user_conversion_summary` |
| **展示** | 左柱：全体用户收藏渗透率 (39.62%)  vs  右柱：购买用户收藏渗透率 (41.42%)；同逻辑展示加购渗透率 |
| **业务解读** | "购买用户的收藏率仅略高于全体用户（41.4% vs 39.6%），说明收藏行为本身不是转化的强信号——需要引导用户直接加购。" |

#### 图表 3：Cohort 留存热力图（Matrix Heatmap）

| 属性 | 内容 |
|------|------|
| **图表类型** | 矩阵热力图 |
| **数据源** | `cohort_retention_detail` |
| **行** | cohort_date（首次访问日期） |
| **列** | retention_day (0~8) |
| **值** | retention_rate_pct |
| **颜色梯度** | 深绿（高留存）→ 白色（中等）→ 深红（低留存） |
| **标注** | 对角线上方标注留存率数值 |
| **业务解读** | "热力图的纵向衰减揭示：无论哪一天进入的用户，留存率都在 Day 1 断崖式下跌。问题与进入时间无关，是产品体验的系统性问题。" |

#### 图表 4：留存衰减曲线 — 分用户群体对比

| 属性 | 内容 |
|------|------|
| **图表类型** | 多条折线图 |
| **数据源** | `cohort_retention_summary`（需要增加或 SQL 计算各分群的留存） |
| **展示** | 购买用户 vs 未购买用户的留存曲线对比 |
| **业务解读** | "发生过购买行为的用户留存显著高于纯浏览用户——首单转化是最有效的留存手段。" |

#### 图表 5：漏斗各阶段用户的行为画像（补充表）

| 属性 | 内容 |
|------|------|
| **图表类型** | 表格/卡片 |
| **数据源** | `user_conversion_summary` |
| **展示** | 各类用户的平均行为数、活跃天数、Session 量 |
| **业务解读** | "到达不同漏斗阶段的用户，其行为深度差异有多大？这帮助判断应该在哪些用户身上投入运营资源。" |

### Drill-Down 设计

```
Page 2 漏斗与留存
  ├─ 漏斗 PV→FAV 断裂 → 深入 Page 4 商品分析（是否是商品推荐问题？）
  ├─ 留存 D1 暴跌 → 深入 Page 3 用户行为（首日有没有关键行为？）
  ├─ 热力图单日 → 查看该日新增用户的 Session 分布
  └─ 特定 Cohort 留存曲线 → 对比该 Cohort 的用户分群构成
```

### 页面结论

> **"转化链非线性：加购 UV(21.5万) 远超收藏 UV(11.4万)——用户跳过收藏直接加购。真正的转化断点是'加购未购'（2 万用户），而非 PV→FAV。留存受 9 天窗口和周末周期效应限制。解决方案：优化加购未购转化 + Session 前 5 推荐位命中率 + 时序差异化运营。"**

### 页面业务价值

- **面试展示**：体现"漏斗分析不只是画图，而是诊断根因"的分析深度
- **业务决策**：直接给出优化优先级——推荐召回 > 购买流程优化
- **数据能力**：漏斗分析 + Cohort 分析是增长分析师的核心能力

## Page 3 — User Behavior（用户行为分析）

### 回答的核心业务问题

> **"用户什么时候活跃？行为模式如何影响转化？如何优化运营时序？"**

### 页面目标

从时间维度揭示用户行为规律，回答三个运营问题：**什么时候推？推什么？推给谁？** 为推送排期、活动策划、产品迭代提供数据支撑。

### KPI 卡片（页面顶部，5 张）

| # | KPI | 数值 | 数据表 | 字段 | 业务含义 |
|---|-----|------|--------|------|----------|
| 1 | **日均 DAU** | ~2.5 万 | `daily_behavior_summary` | AVG(dau) | 平均日活规模 |
| 2 | **周末 DAU 溢价** | +122% | `weekday_behavior_summary` | 对比 avg_dau | 周末比工作日多多少用户 |
| 3 | **活跃峰值时段** | 20-22 点 | `hourly_behavior_summary` | WHERE actions=MAX | 一天中用户最活跃的 2 小时 |
| 4 | **人均日行为数** | ~75 | `daily_behavior_summary` | AVG(avg_actions_per_user) | 用户每天平均产生多少行为 |
| 5 | **短 Session 占比** | 68.1% | `session_stats` | WHERE 1-5 行的 session_pct 之和 | 大部分 Session 无效交互 |

### 图表区（5 个核心图表）

#### 图表 1：DAU & 行为量日度趋势（Area + Line）

| 属性 | 内容 |
|------|------|
| **图表类型** | 面积图 + 折线图组合 |
| **数据源** | `daily_behavior_summary` |
| **面积** | DAU（蓝色渐变面积） |
| **折线** | 购买率 %（绿色折线，双轴） |
| **标注** | 周末区域用浅色底色标识；标注 DAU 峰值日和购买率峰值日 |
| **业务解读** | "DAU 周末飙升但购买率在周末是否同比例提升？如果没有，说明周末流量质量低。" |

#### 图表 2：24 小时行为分布热力图

| 属性 | 内容 |
|------|------|
| **图表类型** | 堆叠柱状图（按行为类型分色）或 24 小时环形热力图 |
| **数据源** | `hourly_behavior_summary` |
| **X 轴** | 0-23 小时 |

#### 图表 3：周末 vs 工作日行为对比

| 属性 | 内容 |
|------|------|
| **图表类型** | 分组柱状图（Clustered Bar） |
| **数据源** | `weekday_behavior_summary` |

## Page 4 — Product Analysis（商品与类目分析）

### 回答的核心业务问题

> **"哪些商品/类目在浪费曝光资源？高转化商品是否获得了足够流量？"**

### 页面目标

从商品和类目维度诊断**流量分配效率**：识别被低估的高转化商品、曝光过度但转化低下的商品、以及类目层级的资源错配。

### KPI 卡片（页面顶部，5 张）

| 2 | **总类目数** | 8,788 | `category_conversion` | COUNT(DISTINCT category_id) | 类目广度 |

| 迁移箭头悬停 | 悬停某条迁移箭头 | Tooltip 显示具体策略和预期 KPI |
| 交叉表单元格点击 | 点击某单元格 | 查看该交叉群体的 Top 类目偏好 |

### Drill-Down 设计

```
Page 5 用户分群
  ├─ 某个 Cluster → 该群体详细特征 → 该群体的 Top 10 偏好类目
  ├─ 某个 Cluster → 该群体的行为分布 → 与全体用户对比
  ├─ 策略卡片 → 策略效果预估 → 推荐触达时机（从 Page 3 的时段分析获取）
  └─ 迁移路径 → 如果 C3→C4 成功 → 预估 GMV 增量
```

### 使用的数据表

| 表名 | 用途 |
|------|------|
| `user_cluster_summary` | KPI 1-5, 图表 1-5 |
| `user_cluster_result` | 下钻分析（个体用户标签） |
| `user_segment_summary` | 图表 6 |
| `category_conversion` | 下钻偏好分析 |

### 页面结论

> **"28.7 万用户可划分为 5 个差异化群体。运营优先级排序：P0 → 维护 C1+C2（31% 用户，贡献最高购买率），P1 → 转化 C3+C4（48.5% 用户，购买率不足 5%），P2 → 引导 C0（20.3%，高粘性低转化）。ROI 最高的策略是首单券推动 C3（8.4 万人）完成首次购买——每 1% 转化率提升带来 840+ 新购买用户。建议按'C3→C4→C1→C2'的阶梯路径设计用户成长体系，配合 Page 3 的时段策略进行精准触达。"**

- **数据能力**：这是数据驱动用户运营的核心能力——分群→策略→KPI→追踪

## 数据准备清单

### 需要在 Power BI 中创建的计算列/度量值

| 度量值名称 | DAX 公式 | 用途 |
|-----------|----------|------|
| `Total Users` | `SUM(user_cluster_summary[user_cnt])` | 总用户数 |
| `Overall Buy Rate` | `DIVIDE(SUM(buy_users), SUM(total_users))` | 整体购买率 |
| `PV to FAV Drop Rate` | `1 - [FAV rate]` | 漏斗流失率 |
| `Problem Items PV %` | `DIVIDE(SUM(high_exposure[...][pv_cnt]), SUM(item_conversion[pv_cnt]))` | 问题商品曝光占比 |
| `Weekend DAU Premium` | `DIVIDE([Weekend DAU] - [Weekday DAU], [Weekday DAU])` | 周末溢价 |
| `C3 Conversion Lift` | `[C3 users] * 0.01 * 0.3` | C3 转化率提升 1% 预估 |

### 建议新增的数据表（可选优化）

| 维度 | 旧版设计 | 新版设计（本文档） |
