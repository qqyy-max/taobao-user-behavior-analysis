## 1. 策略架构

```
输入
  Analyst 已校验的分析结论
      │
      ▼
分层匹配
  用户群体 → 策略模板 → 定制化调整
      │
      ▼
四要素填充
  时机 × 渠道 × 内容 × KPI
      │
      ▼
优先级排序
  P0 (ROI 最高) → P1 (规模最大) → P2 (长期价值)
      │
      ▼
输出
  3-5 条可执行策略，按优先级排列
```

**关键约束**：
- Strategist Agent **严禁查数据**，仅基于输入的分析结论制定策略
- 禁止输出无法落地的建议（如"提升用户体验"、"优化算法"）
- 每条策略必须针对具体用户群体（引用 Cluster ID 或 freq_group）

## 3. 触达时机策略

### 3.1 时段 × 群体矩阵

| 时段 | 最佳触达群体 | 触达内容 | 理由 |
|------|-------------|----------|------|
| **09:00-09:30** | C1, C4 (工作日买家) | 促销 Push、购物车提醒 | 购买率峰值 10:00（2.62%）前 30 分钟 |
| **10:00-11:00** | C2, 已购用户 | 新品推荐、复购提醒 | 购买率最高时段（2.62%） |
| **14:00-16:00** | C4 (潜力转化) | 品类优惠券 | 下午次要购买高峰 |
| **19:00-20:00** | C0, C3 | 内容推荐、直播预告 | 晚间流量高峰前（21:00）1 小时 |
| **周六 10:00** | C3 (周末战士, 67.4% 周末行为) | 加购未购限时折扣 | C3 周末活跃度最高 |
| **周六晚间** | C0 (探索型) | 直播种草、新品类发现 | 周末逛 > 买，适合内容运营 |
| **周三/四 14:00** | C4 (工作日买家, 仅41.6%周末) | 常购清单补货 | C4 周末行为占比最低 |
| **每日** | C2 (核心高价值) | 会员权益提醒 | C2 周末/工作日分布均衡(49.5%) |

### 3.2 时段触达规则

```yaml
rules:
  - name: "购买高峰前 30 分钟触达"
    condition: "目标群体在工作日有购买行为"
    action: "在 10:00 购买峰值前 30 分钟发送促销 Push → 9:30"

  - name: "流量高峰前置内容"
    condition: "目标群体以浏览/发现为主"
    action: "在 21:00 流量峰值前 1-2 小时推送内容/直播/种草 → 19:00"

  - name: "避免凌晨触达"
    condition: "时段在 2:00-6:00"
    action: "禁止任何 Push/短信触达，避免打扰用户造成卸载"

  - name: "周末 ≠ 工作日"
    condition: "is_weekend = true"
    action: "周末推内容/直播/种草 → 工作日推促销/优惠券"

  - name: "基于群体的时段匹配"
    condition: "已知群体周末占比"
    mapping:
      C3_weekend_67pct: "周六 10:00 触达"
      C4_weekend_41pct: "周三/四 14:00 触达"
      C1_weekend_47pct: "工作日 9:30 或 周末 10:00"
```

## 4. 渠道策略

### 4.1 渠道 × 群体映射

| 渠道 | 适用群体 | 适用场景 | 频率限制 |
|------|----------|----------|----------|
| **Push 推送** | 所有群体 | 促销、提醒、召回 | ≤2 次/天 |
| **站内信** | C2, C1 (高价值) | 会员权益、新品内测 | ≤3 次/周 |
| **短信** | C2, 超级用户 | VIP 活动、大促预告 | ≤1 次/周 |
| **站内弹窗** | C0, C3 (高浏览) | 首单券、签到打卡 | ≤1 次/Session |
| **站内推荐位** | C0 (探索型) | 品类发现、个性化首页 | 实时 |
| **邮件** | C2, 已购用户 | 周报、月度总结 | ≤1 次/月 |

### 4.2 渠道选择规则

```yaml
rules:
  - priority: P0
    group: C2, 超级用户
    channels: ["Push", "短信", "站内信"]  # 多渠道覆盖
    reason: "核心用户值得高成本触达"

  - priority: P1
    group: C3, C4, 加购未购
    channels: ["Push", "站内弹窗"]  # 双渠道
    reason: "转化潜力大，成本适中"

  - priority: P2
    group: C0, 沉默用户
    channels: ["站内推荐", "Push"]  # 低成本
    reason: "探索/召回阶段，不宜高成本触达"
```

## 6. KPI 设定规范

### 6.1 KPI 公式

| KPI 类型 | 公式 | 验证方式 |
|----------|------|----------|
| **转化提升** | `(新转化率 - 旧转化率) / 旧转化率 × 100` | A/B 实验 p<0.05 |
| **增量购买** | `目标用户数 × 转化率提升幅度 × 人均购买次数` | 实验组 vs 对照组 |
| **ROI** | `增量 GMV / 策略成本` | 月度复盘 |
| **留存提升** | `实验组 Day N 留存 - 对照组 Day N 留存` | Cohort 分析 |
| **ARPU 提升** | `实验组人均购买 - 对照组人均购买` | t-test |

### 6.2 KPI 设定规则

```yaml
rules:
  - rule: "KPI 必须包含基线 + 目标 + 提升幅度"
    example: "购买率 0.8%(基线) → 2.0%(目标) → +150%"
    NOT: "提升购买率"  # 禁止空泛表述

  - rule: "KPI 必须有量化分母"
    example: "新增 840 名购买用户（C3 群体 84K × 1pp）"
    NOT: "增加大量购买用户"  # 禁止说"大量"

  - rule: "KPI 必须可追踪"
    example: "Push 触达后 24h 内购买率"
    NOT: "长期提升购买率"  # 太长，无法归因
```

## 7. 策略优先级框架

### 7.1 优先级判定矩阵

```
                    群体规模 (user_cnt %)
                    小 (<12%)    中 (12-25%)    大 (>25%)
购买率  高 (>5%)    P0-精准维护    P0-规模维护     P0-核心
购买率  中 (2-5%)   P1-深度转化    P1-批量转化     P0-规模转化
购买率  低 (<2%)    P2-观察        P1-尝试激活     P1-首单突破
```

### 7.2 优先级定义

| 优先级 | 含义 | 投入资源 | 预期周期 | 示例 |
|--------|------|----------|----------|------|
| **P0** | 最高优先级，直接影响 GMV | 高 (多渠道路触达) | 即刻执行 | C2 复购维护、加购催转 |
| **P1** | 高优先级，规模转化机会 | 中 (双渠道触达) | 1-2 周内执行 | C3 首单券、C4 激活 |
| **P2** | 中等优先级，长期价值 | 低 (单渠道/自动) | 1 个月内执行 | C0 内容种草、沉默召回 |
| **P3** | 低优先级，观察为主 | 最低 (仅站内) | 季度执行 | 低频用户的日常签到 |

## 8. 用户迁移阶梯

### 8.1 目标迁移路径

```
C3 (高浏览低转化, 29.3%, 购买率0.8%)
    │  首单券 + 简化路径
    ▼
C4 (潜力转化, 19.2%, 购买率4.2%)
    │  品类优惠券 + 加购催转
    ▼
C1 (高价值, 11.1%, 购买率5.2%)
    │  会员升级 + 常购清单
    ▼
C2 (核心高价值, 20.1%, 购买率9.4%)
    │  权益维护 + 复购激励
    ▼
超级用户 (0.3%, 购买率81.8%)
```

### 8.2 每阶段迁移策略

| 迁移阶段 | 关键动作 | 转化门槛 | 预期转化率 |
|----------|----------|----------|-----------|
| C3 → C4 | 首单后自动升级 | 完成 1 次购买 | 2-5% (首单券推动) |
| C4 → C1 | 购买 ≥3 次 | 3 次购买 | 20-30% (品类券推动) |
| C1 → C2 | 购买 ≥10 次 OR 复购 ≥5 次 | 高频购买 + 复购 | 40-50% (会员体系推动) |
| C0 特殊路径 | 品类收窄 → 首单 | 完成 1 次购买 | 5-10% (内容种草推动) |

## 9. 禁出策略

以下策略在任何情况下都不应输出：

| 策略 | 理由 |
|------|------|
| "提升用户体验" | 无法度量、无法执行 |
| "优化推荐算法" | 不是运营策略，是产品/技术策略 |
| "加大营销投入" | 无具体金额、无渠道、无目标 |
| "加强用户教育" | 无法量化效果 |
| "提高商品质量" | 运营团队无法执行 |
| "增加用户粘性" | 没有定义"粘性"是什么指标 |
| "全量 Push 推送" | 无差异化 = 无效触达 + 增加卸载率 |
| "做一场大促" | 无时间、无群体、无 KPI |

**替代方案**：

| 禁出 | 替代 |
|------|------|
| "提升用户体验" | "简化 C3 用户的购买路径：减少从浏览到支付的步骤数，A/B 测试 3 步 vs 5 步的购买率差异" |
| "优化推荐算法" | "对曝光排名 >500,000 的商品降权 20%，将释放的曝光分配给转化排名 <10,000 的冷门商品" |
| "加大营销投入" | "投入 ¥X，通过 Push 渠道触达 84K C3 用户，首单券面额 ¥Y，预期回收 ¥Z GMV" |

## 10. Strategist Agent Prompt

```yaml
system: |
  你是运营策略师，基于已验证的数据结论制定差异化运营策略。

  ## 规则

  - **严禁查数据**，只基于输入的分析结论制定策略
  - 每条策略必须针对具体用户群体（引用 Cluster ID 如 C0/C2 或 freq_group 如高频/沉默）
  - 策略数量：3-5 条，按 P0→P1→P2 优先级排序
  - 禁止无法落地的建议（见禁出策略清单）

  ## 每条策略必须包含

  - **目标群体**：具体 Cluster ID 或频率分组 + 人数/占比
  - **触达时机**：具体时间（如"周六 10:00"而非"周末"）
  - **具体动作**：渠道 + 内容 + 触发条件（如"加购后 48h 未购买发送 Push"）
  - **预期 KPI**：可量化的目标（如"购买转化率 +25%"而非"提升转化"）

  ## 优先级框架

  P0 → 核心高价值用户维护 (C2, C1) + 加购未购催转
  P1 → 高浏览低转化突破 (C3) + 潜力用户激活 (C4)
  P2 → 探索型引导 (C0) + 沉默用户召回

  ## 输出格式

  【P0】策略名称
    - 目标群体：
    - 触达时机：
    - 具体动作：
    - 预期 KPI：

  【P1】策略名称
    ...

  【数据依据】
  简要说明策略背后的数据支撑（从输入的分析结论中引用）
```
