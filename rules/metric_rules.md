> **版本**：v1.0 | 2026-06-08
> **适用范围**：Agent 分析输出、Power BI Dashboard、运营策略 KPI 设定
> **设计原则**：每个指标必须可计算、可校验、可对比。优先使用 UV（去重用户数）计算转化率，非行为次数。

## 1. 指标分层架构

```
┌─────────────────────────────────────────────┐
│  L1 - 北极星指标                             │
│  用户购买率 · GMV 代理(购买次数) · DAU          │
├─────────────────────────────────────────────┤
│  L2 - 过程指标                               │
│  转化漏斗各阶段渗透率 · 留存率 · Session 购买率   │
├─────────────────────────────────────────────┤
│  L3 - 诊断指标                               │
│  类目广度 · 时段集中度 · 加购→购买率 · 复购率     │
├─────────────────────────────────────────────┤
│  L4 - 运营指标                               │
│  分群转化率 · 触达响应率 · 策略 ROI             │
└─────────────────────────────────────────────┘
```

**Agent 规则**：
- L1 指标必须在每次分析报告的【数据摘要】中列出
- L2 指标在漏斗/留存分析场景中必须输出
- L3 指标在分群/商品诊断时输出
- L4 指标仅在制定运营策略时输出

## 2. 流量指标

### 2.1 DAU (Daily Active Users)

| 属性 | 内容 |
|------|------|
| **定义** | 一天内至少产生 1 条行为记录的去重用户数 |
| **计算公式** | `DAU = COUNT(DISTINCT user_id) WHERE dt = $date` |
| **数据源** | `daily_behavior_summary.dau` |
| **业务含义** | 平台每日活跃规模。DAU 趋势反映平台增长健康度。 |
| **⚠️ 陷阱** | 周末 DAU 通常 +16%~+122%，但购买率可能下降，不宜单独用 DAU 判断平台健康度 |

**变体**：
- **WAU**（周活）：9 天窗口无法计算，需 ≥14 天数据
- **MAU**（月活）：9 天窗口无法计算

### 2.2 UV (Unique Visitors)

| 属性 | 内容 |
|------|------|
| **定义** | 指定时间段/维度内的去重用户数 |
| **计算公式** | `UV = COUNT(DISTINCT user_id) [WHERE condition]` |
| **数据源** | 各聚合表 `uv` 字段 |
| **业务含义** | 最基础的受众规模度量 |

**Agent 规则**：提及任何转化率时必须明确说明分母是 UV 还是行为次数。

## 3. 行为指标

### 3.1 PV (Page View)

| 属性 | 内容 |
|------|------|
| **定义** | 浏览行为的总次数 |
| **计算公式** | `PV = COUNT(*) WHERE behavior_type = 'pv'` |
| **数据源** | `daily_behavior_summary.pv_cnt` / `user_profile.pv_cnt` |
| **业务含义** | 平台内容消费总量的代理指标 |
| **人均 PV** | `人均 PV = PV / UV` — 反映用户参与深度 |

### 3.2 收藏数 (FAV Count)

| 属性 | 内容 |
|------|------|
| **定义** | 收藏行为的总次数 |
| **计算公式** | `FAV = COUNT(*) WHERE behavior_type = 'fav'` |
| **数据源** | `daily_behavior_summary.fav_cnt` |
| **业务含义** | 衡量用户兴趣表达。注意：收藏率 ≠ 购买意向强度（已知结论：收藏不是购买的必要前置行为） |

### 3.3 加购数 (CART Count)

| 属性 | 内容 |
|------|------|
| **定义** | 加入购物车行为的总次数 |
| **计算公式** | `CART = COUNT(*) WHERE behavior_type = 'cart'` |
| **数据源** | `daily_behavior_summary.cart_cnt` |
| **业务含义** | 最高意向的用户行为信号。加购→购买转化是核心优化目标。 |

### 3.4 购买数 (BUY Count)

| 属性 | 内容 |
|------|------|
| **定义** | 购买行为的总次数（GMV 代理指标） |
| **计算公式** | `BUY = COUNT(*) WHERE behavior_type = 'buy'` |
| **数据源** | `daily_behavior_summary.buy_cnt` |
| **业务含义** | 因缺少金额字段，以购买次数作为 GMV 的代理指标 |

## 4. 转化指标

### 4.1 购买率 (Buy Rate) — L1 北极星

| 属性 | 内容 |
|------|------|
| **行为维度公式** | `购买率(行为) = BUY_COUNT / TOTAL_ACTIONS × 100` |
| **用户维度公式** | `购买率(用户) = BUY_USERS / TOTAL_USERS × 100` |
| **数据源** | `daily_behavior_summary.buy_rate_pct`（行为维度）/ `user_conversion_summary.buy_rate_pct`（用户维度，67.97%） |
| **业务含义** | 最重要的北极星指标。行为维度 ≈2% 是正常水平；用户维度 67.97% 表示 2/3 用户至少有一次购买。 |

> **Agent 规则**：每次提及购买率必须标注"行为维度"或"用户维度"。两者不可混用。

### 4.2 收藏率 (FAV Rate)

| 属性 | 内容 |
|------|------|
| **行为维度公式** | `收藏率 = FAV_COUNT / TOTAL_ACTIONS × 100` |
| **用户维度公式** | `收藏渗透率 = FAV_USERS / TOTAL_USERS × 100`（39.62%） |
| **业务含义** | 用户兴趣表达强度，但已知非购买强信号 |

### 4.3 加购率 (CART Rate)

| 属性 | 内容 |
|------|------|
| **行为维度公式** | `加购率 = CART_COUNT / TOTAL_ACTIONS × 100` |
| **用户维度公式** | `加购渗透率 = CART_USERS / TOTAL_USERS × 100`（75.0%） |
| **业务含义** | 加购是真正购买前置信号。加购渗透率 75% vs 收藏渗透率 40% 说明用户偏好直接加购。 |

### 4.4 CVR (Conversion Rate — 阶段间转化率)

| 转化阶段 | 公式 | 说明 |
|----------|------|------|
| PV → FAV | `FAV_UV / PV_UV` | ⚠️ 39.79%，流失 60.21% |
| PV → CART (skip FAV) | — | 用户跳过收藏直接加购，Sankey 图定量 |
| FAV → CART | `CART_UV / FAV_UV` | ⚠️ 可能 >100%（收藏用户 < 加购用户），是伪指标 |
| CART → BUY | `BUY_UV / CART_UV` | 68.25%，真正的转化瓶颈之一 |

> **Agent 规则**：必须使用漏斗各阶段 UV（非行为次数）计算阶段间转化率。FAV→CART 因源群体小于目标群体，可能 >100%，需特别说明。结论：**使用 Sankey 图替代单路径漏斗**以展示非线性路径。

### 4.5 整体转化漏斗渗透率

| 阶段 | 用户数 | 渗透率 | 计算方式 |
|------|--------|--------|----------|
| PV | 285,816 | 100.00% | 基准 |
| FAV | 113,717 | 39.79% | `FAV_UV / PV_UV` |
| CART | 215,167 | 75.29% | `CART_UV / PV_UV` |
| BUY | 195,078 | 68.25% | `BUY_UV / PV_UV` |

> **注意**：这不是严格漏斗（各阶段非互斥），而是渗透率。同一用户可以出现在所有 4 个阶段。

## 5. 留存指标

### 5.1 Day N 留存率

| 属性 | 内容 |
|------|------|
| **定义** | 在 Day 0 首次活跃的用户，在 Day N 仍活跃的比例 |
| **计算公式** | `DayN_Retention = USER_COUNT(active on cohort_date + N) / USER_COUNT(first_active on cohort_date) × 100` |
| **数据源** | `cohort_retention_detail.retention_rate_pct` |
| **业务含义** | 衡量平台粘性和用户回访习惯 |

**已知数据（11/25 Cohort, N=204,904）**：

| Day | 对应日期 | 留存率 | 解读 |
|-----|----------|--------|------|
| D0 | 11/25 (Sat) | 100.0% | 基准 |
| D1 | 11/26 (Sun) | 78.8% | 次日留存，1/5 用户首日后不回访 |
| D2-D6 | — | 76.0%-77.3% | 留存极其平坦（仅降 1.5pp） |
| D7 | 12/02 (Sat) | 98.5% | ⚠️ 周末周期效应，非真实留存 |
| D8 | 12/03 (Sun) | 98.3% | ⚠️ 周末周期效应 |

> **Agent 规则**：
> 1. 提及 D7 留存时必须标注"周末周期效应"
> 2. 9 天窗口无法评估长期留存，必须声明此局限
> 3. 需要 ≥30 天数据排除周期效应

### 5.2 Cohort 定义

| 属性 | 内容 |
|------|------|
| **定义方式** | 按用户首次活跃日期分组（`MIN(dt) for each user`） |
| **数据表** | `cohort_retention_detail` — 每行 = (cohort_date, retention_day, retention_rate_pct) |
| **注意事项** | 71% 用户首次活跃在 11/25，数据受单 Cohort 主导 |

## 6. Session 指标

### 6.1 Session 定义

| 属性 | 内容 |
|------|------|
| **定义** | 同一用户连续行为间隔 ≤30 分钟视为同一 Session |
| **数据源** | `session_summary`（明细）/ `session_stats`（聚合） |

### 6.2 Session 行为数分组

| 分组 | Session 占比 | 购买率 | 运营含义 |
|------|-------------|--------|----------|
| 1 次 | — | — | 瞬间跳出 |
| 2-5 次 | 68% | 7.5% | "冷漠期" — 大多数 Session 无购买 |
| 6-20 次 | — | **13.0%** | "临界点" — 购买率翻倍 |
| 21-50 次 | — | — | 高意向 |
| 50+ 次 | — | — | 深度购买 Session |

> **Agent 规则**：分析 Session 时必须标注"6 行为临界点"这一已知结论。

### 6.3 Session 购买率

| 属性 | 内容 |
|------|------|
| **公式** | `Session_Buy_Rate = Sessions_with_Buy / Total_Sessions × 100` |
| **数据源** | `session_stats.buy_rate_pct` |
| **关键发现** | 突破 6 行为 → 购买率 7.5% → 13.0%（翻倍） |

## 7. 商品与类目指标

### 7.1 商品/类目购买率

| 属性 | 内容 |
|------|------|
| **公式（行为维度）** | `Item_Buy_Rate = BUY_CNT / PV_CNT × 100` |
| **公式（用户维度）** | `Item_User_Buy_Rate = BUY_UV / UV × 100` |
| **数据源** | `item_conversion.buy_rate_pct` / `category_conversion.buy_rate_pct` |

> ⚠️ `buy_rate_pct > 100%` 可能发生（搜索直达型商品），属于正常数据，需标注原因。

### 7.2 曝光-转化排名差距

| 属性 | 内容 |
|------|------|
| **公式** | `Gap = exposure_rank - conversion_rank` |
| **数据源** | `high_exposure_low_conversion_items.exposure_conversion_gap` |
| **业务含义** | 正值 = 曝光排名好于转化排名（曝高转低）。差距 >500,000 的商品建议降权。 |

### 7.3 高曝光低转化商品定义

| 属性 | 内容 |
|------|------|
| **阈值** | `pv_cnt ≥ P75`（≥6 次）AND `buy_rate_pct ≤ 中位数`（≤0%） |
| **规模** | 512,540 件（占全量 ~19.8%） |
| **数据源** | `high_exposure_low_conversion_items` |

### 7.4 搜索直达型商品

| 属性 | 内容 |
|------|------|
| **定义** | `buy_cnt > 0 AND pv_cnt = 0` — 有购买但无浏览记录 |
| **规模** | 11,781 件 |
| **业务含义** | 用户通过搜索/推荐直达购买，"被低估的宝藏"，应增加搜索曝光 |

## 8. 用户价值指标

### 8.1 类目广度 (Category Diversity)

| 属性 | 内容 |
|------|------|
| **公式** | `COUNT(DISTINCT category_id)` per user |
| **数据源** | `user_profile.category_diversity` |
| **业务含义** | 衡量用户兴趣广度。C0 = 43.6（极广），C4 = 11.3（集中）。 |

### 8.2 加购→购买率 (CART-to-BUY Rate)

| 属性 | 内容 |
|------|------|
| **公式** | `BUY_CNT / CART_CNT × 100` |
| **数据源** | `user_cluster_summary.cart_to_buy_rate` |
| **⚠️ 陷阱** | >100% 表示复购（同商品多次购买 > 一次加购）。C2=137.7% → 复购型用户。 |

### 8.3 用户价值评分

| 维度 | 权重 | 评分逻辑 |
|------|------|----------|
| 购买率 | 35% | 按 percentile rank (0~1) × 35 |
| 复购率 | 25% | `is_repeat_buyer` × 25 |
| 活跃天数 | 20% | `active_days / 9` × 20 |
| 类目广度 | 10% | `category_diversity / max_category_diversity` × 10 |
| 近 7 日活跃 | 10% | `recent_7d_actions_pct / 100` × 10 |

**评分区间**：

| 评分 | 用户层级 | 对应 Cluster |
|------|----------|--------------|
| 80-100 | 核心高价值 | C2 |
| 60-79 | 高价值 | C4 |
| 40-59 | 潜力转化 | C3 |
| 20-39 | 探索型浏览 | C0 |
| 0-19 | 高浏览低转化 | C1 (最大群体) |

## 9. 时间维度指标

### 9.1 周末占比 (Weekend Ratio)

| 属性 | 内容 |
|------|------|
| **公式** | `行为在周末的次数 / 总行为次数 × 100` |
| **数据源** | `user_features.weekend_ratio` / `cluster_temporal_profile.avg_weekend_ratio_pct` |
| **关键值** | C3=67.4%（周末战士），C4=41.6%（工作日买家） |

### 9.2 时段比率 (Morning/Afternoon/Evening/Night Ratio)

| 时段 | 小时范围 | 业务含义 |
|------|----------|----------|
| 深夜 (Night) | 0:00-6:00 | 低流量低转化，避免 Push |
| 上午 (Morning) | 6:00-12:00 | 购买率峰值窗口（10:00 最高 2.62%） |
| 下午 (Afternoon) | 12:00-18:00 | 次要活跃期 |
| 晚间 (Evening) | 18:00-24:00 | 流量峰值窗口（21:00 流量最高，购买率 1.73%） |

### 9.3 时段集中度 (Hour Concentration)

| 属性 | 内容 |
|------|------|
| **定义** | 行为在 24 小时内的分布集中度（类 Gini 系数） |
| **数据源** | `user_features.hour_concentration` |
| **业务含义** | 越高说明行为越集中在少数时段，适合精准触达 |

## 10. 指标校验规则

### 10.1 硬约束（违反时必须标注为异常）

| # | 约束 | 检查方式 |
|---|------|----------|
| 1 | `BUY_UV ≤ PV_UV` | 购买用户数不得大于浏览用户数 |
| 2 | `FAV_UV ≤ PV_UV` | 收藏用户数不得大于浏览用户数 |
| 3 | `CART_UV ≤ PV_UV` | 加购用户数不得大于浏览用户数（⚠️ 存在搜索直达例外） |
| 4 | `留存率 ≤ 100%` | 任何 Day N 留存率不超过 100% |
| 5 | `转化率(用户维度) ≤ 100%` | 用户维度转化率不超过 100% |
| 6 | `行为购买率 ≤ 100%` | 行为维度购买率不超过 100% |

### 10.2 软约束（违反时需标注 Explanation）

| # | 约束 | 说明 |
|---|------|------|
| 7 | `购买率(行为维度)` 正常范围 1.5%-3.0% | 超范围需说明原因 |
| 8 | `buy_rate_pct > 100%` for category/item | 搜索直达商品，需标注 |
| 9 | `cart_to_buy_rate > 100%` for user cluster | 复购信号，需标注 |
| 10 | D7 留存率 > D1 留存率 | 周末周期效应，需标注 |

### 10.3 Agent 输出规范

所有指标输出必须满足：

1. **标注维度**：行为维度 vs 用户维度
2. **标注数据源**：来自哪个表/字段
3. **标注时间窗口**：全量 9 天 vs 特定日期
4. **标注分母**：UV（去重用户）vs Actions（行为次数）
5. **标注局限性**：9 天窗口限制、周末周期效应等
